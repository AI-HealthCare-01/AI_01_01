# Mindsight Style Brief

## 1. 목적
이 문서는 Mindsight 서비스의 전반적인 시각 방향과 UX 톤을 정의한다.  
레퍼런스 이미지를 그대로 복제하지 않고, 공통된 색감·여백·레이아웃·정보 밀도를 추출해 실제 제품 디자인 시스템으로 변환하는 것이 목적이다.

---

## 2. 제품 성격
Mindsight는 정신건강 자기관리 웹서비스다.  
기록, 회고, 체크인, CBT, 챌린지, 대시보드, 리포트, 커뮤니티, 관리자 기능을 포함한다.

디자인이 전달해야 하는 인상:
- 차분함
- 부드러움
- 정돈됨
- 안전함
- 신뢰감
- 과하지 않은 따뜻함

피해야 하는 인상:
- 병원 EMR/의료기기 같은 딱딱함
- 게임형/보상형 서비스처럼 보이는 과한 장식
- 템플릿형 B2B 대시보드 느낌
- 지나치게 감성적이거나 유아적인 무드

---

## 3. 레퍼런스 이미지 해석 요약
레퍼런스 이미지에서 공통적으로 가져갈 요소:
- 부드러운 파스켈 계열 색상의 그라데이션
- 글래스모피즘 포인트
- 라운드 카드
- 가벼운 그림자와 약한 보더
- 한 화면 안에서 정보량은 많지만 답답하지 않은 구성
- 부드러운 gradient mass 사용
- CTA는 보라 계열 중심, 나머지는 파스텔 보조색 활용

버릴 요소:
- 템플릿형 진한 사이드바
- 카드 안에 카드가 반복되는 밀도 높은 구성
- 장식용 블러/글로우 과다 사용
- 원색 중심의 자극적 컬러 체계

---

## 4. 핵심 디자인 방향

### 4.1 전체 무드
- 부드러운 파스텔 그라데이션 배경
- 글래스모피즘 포인트
- 넓은 여백
- 라운드 처리된 컴포넌트
- 최소한의 장식
- 사용자가 피곤하거나 예민한 상태여도 읽기 쉬운 구조

### 4.2 시각적 계층
- 페이지 제목 → 섹션 제목 → 카드 제목 → 본문 → 보조 텍스트
- 숫자/점수/상태 라벨은 더 명확하게
- 한 화면에서 너무 많은 계층을 만들지 않는다

### 4.3 정보 밀도
- 기본은 “가볍고 정돈된 화면”
- 리스트/대시보드는 풍부하게 보여주되, 카드 간 간격을 충분히 둔다
- 관리자 화면은 사용자 화면보다 조밀할 수 있으나 브랜드 톤은 유지한다

---

## 5. 컬러 방향

> 아래 값은 구현 시작용 기본값이다. 세부 조정 가능.

### Base / Surface
- `bg.base`: `#FAFBFF`
- `bg.soft`: `#F6F3FB`
- `surface.base`: `#FFFFFF`
- `surface.alt`: `#F8F7FC`
- `border.soft`: `#E9E7F2`

### Text
- `text.primary`: `#1F2430`
- `text.secondary`: `#687085`
- `text.tertiary`: `#98A1B3`

### Brand / Accent
- `brand.primary`: `#7C6CF6`
- `brand.primary.hover`: `#6D5CE8`
- `accent.pink`: `#F5B8D0`
- `accent.sky`: `#BEE7F3`
- `accent.mint`: `#CDEEE5`
- `accent.peach`: `#F6D8C8`
- `accent.lavender`: `#D9CCF7`

### Semantic
- `status.success`: `#5CC89B`
- `status.warning`: `#F3B764`
- `status.danger`: `#EB7282`
- `status.info`: `#7EAEF7`

### Gradient
- `gradient.hero.1`: `linear-gradient(135deg, #E8F3FF 0%, #F8E8F5 100%)`
- `gradient.hero.2`: `linear-gradient(135deg, #F5E9FF 0%, #E8FBF8 100%)`
- `gradient.card.soft`: `linear-gradient(135deg, #FFF7FB 0%, #F4F7FF 100%)`

### 컬러 사용 원칙
- 기본 배경은 밝고 중립적으로 유지
- 브랜드 색은 CTA/포커스/선택 상태에만 집중 사용
- 파스텔 색은 보조 강조와 카드 배경에 제한적으로 사용
- 위험/오류는 red 계열을 쓰되 과장하지 않음
- 그래프는 읽기 쉬운 대비를 확보하되 과한 원색 사용 금지

---

## 6. 타이포그래피 방향

### 원칙
- 본문 가독성 최우선
- 화면마다 다른 폰트/크기 체계를 만들지 않는다
- 점수/날짜/지표는 숫자 가독성이 좋아야 한다
- 긴 문장은 짧고 명확한 한국어로 유지

### 권장 계층
- Page title
- Section title
- Card title
- Body
- Caption / Helper

### 톤
- 부드럽지만 모호하지 않게
- 감정적 과장 금지
- 의료적 단정 금지
- 안내문은 짧고 구조적으로

---

## 7. 레이아웃 원칙

### 공통
- 화면 상단 여백 충분히 확보
- 카드 간 간격을 좁히지 않는다
- 한 화면에 3~5개의 주요 블록을 기본으로 한다
- 레이아웃 리듬은 카드/섹션 단위로 만든다
- 정보가 많아도 숨 쉴 여백을 유지한다

### 모바일 우선
- 단일 컬럼 중심
- thumb zone 고려
- CTA는 손이 닿기 쉬운 위치
- 탭/버튼/세그먼트는 충분한 터치 영역 확보

### 데스크톱
- 카드 그리드를 부분적으로 사용 가능
- 하지만 모바일 구조를 무리하게 깨지 않는다
- 넓은 화면에서도 최대 콘텐츠 폭을 제어한다

---

## 8. 화면별 UX 방향

### 8.1 홈
목표:
- 오늘 해야 할 행동을 쉽게 시작
- 서비스가 복잡해 보이지 않게 구성

구성:
- 상단 요약 hero
- 체크인 / 일기 쓰기 / 챌린지 / CBT 빠른 진입
- 최근 상태 요약
- 최근 기록/리포트 진입점

### 8.2 체크인
목표:
- 빠르게 기록
- 질문이 부담스럽지 않게

원칙:
- 한 번에 너무 많은 질문 노출 금지
- 선택형 버튼/세그먼트 우선
- 슬라이더는 최소화

### 8.3 진단척도
목표:
- 부담 없는 수행
- 결과는 비진단형 요약

원칙:
- 공식 문항 유지
- 톤만 부드럽게
- 진행률과 다음 행동이 명확해야 함

### 8.4 대시보드
목표:
- 현재 상태와 변화 추이를 동시에 이해
- 복잡하지 않게 비교 가능

원칙:
- 우울/불안/불면 그래프는 한 화면 안 세로 배치
- 7일과 4주 평균 모드를 명확히 분리
- 활동 대시보드는 “기록한 날/활동한 날” 중심

### 8.5 일기
목표:
- 쓰기에 집중
- 회고는 따로 쉽게 가능

원칙:
- 입력 화면에 방해 요소 최소화
- 저장 피드백 짧고 명확하게
- 목록은 본문 일부만 노출

### 8.6 게시판
목표:
- 최신 글 소비가 쉽고, 너무 자극적이지 않은 피드

원칙:
- 단일 컬럼 피드 중심
- 탭과 검색은 상단 고정 리듬
- 카드 내 텍스트 계층 고정
- 공지와 일반 글은 구분

### 8.7 마이페이지
목표:
- 설정 + 내 기록 허브

원칙:
- 첫 화면은 요약 중심
- 상세 기능은 하위 메뉴로 분리
- 활동로그/북마크/문의/리포트는 진입점이 명확해야 함

### 8.8 관리자 콘솔
목표:
- 운영 효율
- 과한 장식보다 기능 중심

원칙:
- 정보 밀도는 높아도 됨
- 브랜드 톤은 유지
- 위험/민감 큐는 더 또렷하게
- 기본 사용자 목록에는 IP 비노출

---

## 9. 컴포넌트 톤
- 카드: soft border + 얕은 shadow
- 버튼: 라운드, 명확한 primary, 과한 입체감 금지
- 입력창: 부드러운 border, 보라 focus
- 탭/세그먼트: pill 형태 가능
- 그래프: 장식보다 해석 우선
- 배지: 의미는 명확하되 색상 의존만 하지 않음

---

## 10. 그림자 / 보더 / 라운드

### Radius
- 입력/버튼: 중간 radius
- 카드: 큰 radius
- 모달: 카드보다 조금 더 크거나 동일

### Shadow
- 얕고 넓게
- 진하고 무거운 그림자 금지

### Border
- 아주 연한 회색 또는 라벤더 계열 사용
- border와 shadow를 동시에 강하게 쓰지 않음

---

## 11. 상태 표현 원칙
- loading, empty, error를 모든 주요 화면에서 정의
- 에러는 색상만으로 표현하지 않는다
- 성공 상태는 짧고 명확하게
- 위험 경고는 시각적으로 구분하되 공포감을 과장하지 않는다

---

## 12. 접근성 원칙
- 명도 대비 확보
- 키보드 포커스 상태 명확히
- 아이콘만으로 의미 전달 금지
- 오류는 텍스트로도 설명
- 그래프는 수치/요약 문장 병행
- 너무 작은 터치 영역 금지

---

## 13. 구현 우선순위
1. 디자인 토큰 확정
2. 공통 UI 컴포넌트 구현
3. 앱 쉘 / 레이아웃 구현
4. 홈 / 체크인 / 대시보드 우선 반영
5. 일기 / 게시판 / 마이페이지 확장
6. 관리자 콘솔 반영

---

## 14. 구현 시 금지 패턴
- 모든 카드에 gradient 적용
- 한 화면에서 파스텔 색상 너무 많이 사용
- 관리자 화면만 완전히 다른 시각 체계 사용
- 과한 글로우, 과한 blur, 과한 hover animation
- 본문형 콘텐츠를 리스트에서 전부 노출
- 그래프를 예쁘게만 만들고 해석 보조 텍스트 생략

---

## 15. 현재 기준 참고 화면
우선 참고 대상:
- 홈: `home4`, `home5`, `home6`, `home7`
- 대시보드: `dashboard4`, `dashboard6`, `dashboard8`, `main1`, `main5`, `main10`
- 피드: `board1`, `board2`, `feed1`
- 폼/설문/마이페이지: `sign-up1`, `survey1`, `survey2`, `mypage`, `mypage2`, `mypage3`
- 관리자: `manage-dashboard`, `manage-dashboard2`, `manage-dashboard3`

## 17. 레퍼런스 정합 강화 (v2)

이번 정합 강화에서 반드시 유지할 기준:
- 앱 공통 쉘은 `라운드 메인 캔버스 + 플로팅 상단 메뉴` 구조를 기본으로 한다.
- 첫 화면은 단순 카드 나열 대신 `큰 히어로 블록 + 대화 프리뷰 카드 + 바로가기 묶음` 리듬을 사용한다.
- 화면 카피는 개발자 설명형 문장(예: "핵심 화면으로 이동", "요약 3건") 대신 사용자 행동 중심 문장으로 작성한다.
- 사용자/관리자 모두 같은 브랜드 토큰을 사용하되, 관리자 화면은 정보 밀도만 높인다.
Mindsight의 UI는  
**“부드럽고 차분한 파스텔 톤 위에, 정돈된 정보 구조와 넓은 여백을 가진 자기관리 서비스”**  
처럼 보여야 한다.
