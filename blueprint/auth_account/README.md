# 로그인 / 회원가입 / 이메일 확인 / 비밀번호 재설정 Blueprint

- 버전: v1.0
- 기준일: 2026-03-02
- 이메일 발송 방식: **Firebase Authentication** 기반 이메일 확인 / 비밀번호 재설정
- 범위:
  - 계정 생성
  - 이메일 확인
  - 비밀번호 재설정
  - 기본 동의 항목
  - 내부 `user_id` / 모델용 `ml_subject_id` 규칙
  - 최초 로그인 후 온보딩
  - 출생년도 수집
  - 초기 진단척도 연결
  - 대시보드 / 모델 초기값 연결

## 핵심 설계 원칙
1. 가입 단계는 **최소 정보만** 받는다.
2. 이메일은 **이메일 소유 확인** 용도로 사용한다. 법적 본인확인으로 표현하지 않는다.
3. 민감정보(정신건강 관련 설문/체크인/위험 관련 정보)는 **온보딩에서 별도 동의 후** 수집한다.
4. `user_id`와 `ml_subject_id`는 분리한다.
5. 초기 진단척도는 **첫 로그인 온보딩에서 1회 필수**로 수행한다.
6. Firebase Auth가 메일 액션을 처리하고, 서비스는 상태 관리/온보딩/내부 ID/프로필 저장을 담당한다.

## 폴더 구성
- `00_overview/` : 설계 원칙, 전체 흐름, 근거 자료
- `01_product/` : UX 플로우, 화면 카피, 이메일 UX
- `02_domain/` : 데이터 명세, 상태값, ID 규칙, 동의 항목
- `03_storage/` : DB 스키마, 매핑 규칙
- `04_backend/` : API 계약, Firebase Admin 연동 포인트
- `05_frontend/` : 화면 설계
- `06_email_firebase/` : Firebase Authentication 이메일 액션 설계
- `07_onboarding/` : 출생년도/성별/초기 진단척도 설계
- `08_security/` : 보안/재인증/rate limit
- `09_implementation/` : 단계별 구현 순서 / acceptance criteria
- `codex_prompts/` : Codex 시작 프롬프트

## 구현 우선순위
1. 계정 상태 / 동의 상태 / ID 규칙 확정
2. Firebase Auth 이메일/비밀번호 인증 연결
3. 회원가입 / 로그인 / 비밀번호 재설정 UI
4. 이메일 확인 후 온보딩 진입 플로우
5. 온보딩 기본정보 + 초기 진단척도 저장
6. 모델 / 대시보드 초기값 생성
