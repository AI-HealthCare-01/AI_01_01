# 핵심 결정사항

## 1. 문의와 피드백을 왜 통합 티켓으로 보나?
- 답변 구조, 상태값, 알림 구조, 관리자 처리 흐름이 동일하다.
- 분리 구현하면 중복이 커지고, 나중에 관리자페이지에서 다시 합쳐야 한다.
- 따라서 내부적으로는 support_ticket 1종 + ticket_type으로 분기한다.

## 2. 왜 '알림 목록'과 '전체 내역'을 분리하나?
- 관리자 알림 목록은 '지금 처리해야 할 것'만 보여야 한다.
- 전체 내역은 검색/감사/재검토를 위한 기록이다.
- 사용자도 마찬가지로 '새 답변 알림'과 '내 문의 내역'은 목적이 다르다.

## 3. 왜 추가문의를 새 티켓으로 만들지 않나?
- 같은 주제의 대화가 흩어져 처리 이력이 깨진다.
- 따라서 추가문의는 기존 티켓 스레드에 메시지를 이어붙이고, 상태만 reopened로 바꾼다.

## 4. 왜 완전 익명을 허용하지 않나?
- 악용/사후 대응/정책 집행이 어려워진다.
- 사용자는 비공개로 느끼되, 내부적으로는 계정 연결이 필요하다.
