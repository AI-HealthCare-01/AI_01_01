# Security & Privacy Notes

## 목적
이 문서는 MindMe 프로젝트의 개인정보, 민감정보, 로그, 권한 처리 원칙을 정리한다.

---

## 1. 기본 원칙
- 최소 수집
- 최소 노출
- 최소 권한
- 목적 제한
- 변경 이력 추적
- 운영 로그와 사용자 데이터 분리

---

## 2. 데이터 분류
### 일반 개인정보
- 이메일
- 닉네임
- 계정 생성일
- 로그인 이력

### 민감정보로 취급
- 진단척도 점수
- 체크인 상태값
- CBT 구조화 결과
- 위험 플래그
- 자유일기/문의 본문 중 정신건강 관련 내용

### 운영 민감정보
- 최근 IP
- 차단 이력
- 관리자 메모
- 신고/모더레이션 판단 기록

---

## 3. 수집 원칙
회원가입 단계:
- 닉네임
- 이메일
- 비밀번호
- 필수 동의

온보딩 단계:
- 출생년도
- 성별(선택)
- 민감정보 처리 동의
- 개인화/모델 개선 동의
- 초기 진단척도

---

## 4. 노출 원칙
### 일반 사용자 화면
- 본인 데이터만 조회 가능
- 활동로그는 요약 중심
- 일기/CBT/문의 본문은 전체 목록에서 과도하게 노출하지 않음

### 관리자 화면
- 권한별 최소 노출
- 기본 사용자 조회 화면에서는 IP 비노출
- 차단/보안 조치 화면에서만 이메일/IP 상세 노출
- 위험 플래그와 민감정보는 상위 권한 우선

---

## 5. 로그 정책
로그에는 아래를 직접 남기지 않는다.
- 비밀번호
- 일기 원문 전체
- CBT 자유 텍스트 원문 전체
- 문의 원문 전체
- 민감정보 상세 본문
- 토큰/시크릿

허용되는 로그 예:
- user_id
- route
- action_type
- status_code
- request_id
- error_code
- queue_type
- audit_event

---

## 6. 인증/계정 보안
- 이메일 인증은 이메일 소유 확인 용도
- 이메일 미인증 계정은 주요 기능 제한
- 비밀번호 재설정은 1회용 토큰/링크 기반
- 비밀번호는 해시 저장
- 관리자 계정은 더 높은 보안 수준 권장
- 권한 변경은 감사 로그 남김

---

## 7. 권한 구조
- Owner
- Admin
- Support
- optional analyst/ml extension

원칙:
- Owner만 정책 수정/모델 변경/배포 승인 가능
- Admin은 admin + support 권한
- Support는 기본 기능만
- analyst/ml extension은 승인 후 부여

---

## 8. 파일/첨부 처리
- 게시판 이미지, 문의 첨부, 리포트 파일은 별도 스토리지에 저장
- 허용 확장자와 크기 제한 필요
- 민감 파일은 공개 URL로 오래 노출하지 않음
- 다운로드 URL은 만료형 우선

---

## 9. 모델/데이터 처리 원칙
- 서비스용 `user_id`와 모델용 `ml_subject_id` 분리
- synthetic와 real user 데이터는 구분 가능해야 함
- 설문 점수는 sparse anchor로 취급
- 모델 재학습/배포는 승인형
- 감사 로그와 모델 버전 기록 유지

---

## 10. 삭제/철회/제한
- 동의 철회 시 기능 제한 범위 명확히 안내
- 계정 탈퇴 정책 별도 정의
- 관리자 차단/제한 조치는 사유와 이력 기록
- 필요 시 삭제 대신 비활성/익명화 처리 검토
